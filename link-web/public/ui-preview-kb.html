Link 采用 Go + Python 双服务架构，职责严格分离：
  • link-go 是主后端，承担 HTTP 接口、任务调度与 UI 契约拼装（handler → service → model ← repository）；
  • link-python 只做计算与分析：RAG 评测、向量化处理，通过 gRPC（高性能大数据）和 MCP（AI 工具调用）与 Go 通信；
  • 存储层分工：MySQL 元数据与配置，Milvus 向量与特征，Neo4j 知识图谱与血缘，Redis 缓存与队列。

设计模式上统一使用 Builder / Factory / Repository / Middleware / Strategy，全链路通过 request_id 串联，写操作强制 idempotency_key。

RAG 评测跑一次要多久？指标有哪些？
14:22
检索过程 2 steps · 260ms done
kb_search 向量检索 Top6 评测相关片段（Milvus） 190ms
rerank 重排序取 Top2，命中评测指标文档 70ms
RAG 评测单次运行时长取决于评测集规模，通常 50–200 条样本约需 2–8 分钟（Python 服务异步跑批，Go 端轮询任务状态）。核心指标体系如下：
  • faithfulness：回答与检索片段的事实一致性，防止 LLM 幻觉；
  • answer_relevancy：生成答案与问题的语义相关度；
  • context_recall：检索结果对 ground-truth 的覆盖率；
  • context_precision：检索结果中相关片段的精确率；
  • answer_correctness：对比标准答案的综合正确率（含 F1）。

指标计算在 link-python/services/evaluation 中逐任务异步执行，结果聚合后持久化到 MySQL，供 Go 端 API 拉取展示。
