# 图谱关系统计边界

`GET /api/v1/graph/stats/relations?kb_id=…` 使用已认证的 `int64` 租户和用户身份，并在每次读取前重新查询 MySQL 知识库授权。有效且未删除的知识库 owner 可读；同租户公共知识库可读。缺少身份不回退到租户或用户 1。统计为完整范围聚合，不采用图谱可视化的 1,000 条加载上限。

Neo4j 关系及其两端 `Entity` 必须同时具有请求的 `tenant_id`、`kb_id`。有向关系和自环均只计一次。`r.type` 用于类型分布；强度按整数截断分桶，平均强度和权重保留实际数值。`chunk_ids` 兼容当前写入的 JSON 字符串、原生字符串数组和空值；损坏数据或数据库错误会返回错误，不伪装为空图。

`POST /api/v1/knowledge-bases/:id/graph/relations` 同样要求有效身份和当前知识库授权，只有 owner 可以写入；公共可读不代表可写。单条和批量写入均在关系上持久化租户、知识库范围。缺少源/目标节点或提交失败不会返回创建成功。

历史单条写入可能留下缺少关系 `tenant_id` / `kb_id` 的边。这些边仍被统计排除，不会在读取时自动补齐。存量数据需另行审计真实来源和权限后制定迁移；不得默认归属 tenant 1，也不得仅凭客户端声明或单端节点推断 owner。本次没有运行历史关系迁移，也没有扩展其他旧图谱端点的行为。
