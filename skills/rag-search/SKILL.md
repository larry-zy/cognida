# RAG Search Skill

此 Skill 提供知识库检索的系统化方法和最佳实践。

## 核心概念

RAG（Retrieval-Augmented Generation）通过检索相关文档来增强生成能力：

1. **查询理解**：解析用户查询意图
2. **检索执行**：从向量数据库查找相关文档
3. **结果处理**：排序、过滤和整合检索结果
4. **答案生成**：基于检索内容生成回答

## 检索策略

### 向量检索
- 适用场景：语义相似度搜索
- 工具：`rag_query`
- 参数：
  - `query`: 查询文本
  - `top_k`: 返回结果数量（默认 15）
  - `threshold`: 相似度阈值（默认 0.0）

### 知识库选择
- 适用场景：指定特定知识库
- 工具：`kb_select`
- 参数：
  - `kb_id`: 知识库 ID
  - `query`: 查询文本
  - `top_k`: 返回结果数量

### 知识库列表
- 适用场景：浏览可用知识库
- 工具：`kb_list`
- 无参数

## 检索流程

### 标准流程

```
1. 理解查询
   ↓
2. 选择检索策略
   ↓
3. 执行检索
   ↓
4. 评估结果
   ↓
5. 整合答案
```

### 查询优化技巧

当检索结果不理想时：

1. **重写查询**
   - 添加关键词
   - 使用同义词
   - 拆分为多个查询

2. **调整参数**
   - 增加 `top_k` 获取更多结果
   - 降低 `threshold` 扩大检索范围
   - 尝试不同的知识库

3. **使用上下文**
   - 结合对话历史
   - 考虑用户背景
   - 理解业务场景

## 工具使用示例

### 基础检索

```json
{
  "tool": "rag_query",
  "parameters": {
    "query": "如何使用向量检索？",
    "top_k": 10,
    "threshold": 0.5
  }
}
```

### 指定知识库检索

```json
{
  "tool": "kb_select",
  "parameters": {
    "kb_id": "tech-docs",
    "query": "API 使用方法",
    "top_k": 5
  }
}
```

### 浏览知识库

```json
{
  "tool": "kb_list",
  "parameters": {}
}
```

## 结果评估

检索结果的质量评估：

### 相关性指标
- 内容与查询的匹配度
- 信息的完整性
- 时效性

### 排序策略
- 语义相似度
- 关键词匹配
- 文档权威性

### 不理想结果的处理

如果检索结果不理想：

1. **检查查询**：是否清晰表达意图
2. **调整参数**：top_k、threshold
3. **尝试不同知识库**：可能其他知识库有更好结果
4. **多轮检索**：使用初次结果优化后续检索

## 最佳实践

1. **明确检索目标**：理解用户真正需要什么
2. **选择合适策略**：向量检索 vs 精确匹配
3. **评估结果质量**：不盲目接受检索结果
4. **持续优化**：根据反馈调整检索策略
5. **结合其他工具**：必要时结合 web_search、sql_execute

## 输出格式

基于检索结果的回答应包含：

```markdown
## 检索结果

### 来源
- 知识库：[知识库名称]
- 检索策略：[向量/混合/精确]
- 检索时间：[时间戳]

### 相关文档
1. [文档标题](文档链接)
   - 相关度：[分数]
   - 关键内容：[摘要]

### 答案
[基于检索结果的整合答案]

### 参考
- 引用的文档列表
```

## 注意事项

- 检索结果可能不完整，需要结合多个来源
- 注意文档的时效性，优先使用最新内容
- 引用来源时保持准确性
- 当检索结果不足时，诚实告知用户
