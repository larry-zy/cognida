# Code Review Skill

此 Skill 提供代码审查的系统化方法和最佳实践。

## 审查框架

使用以下框架进行全面的代码审查：

### 1. 正确性审查
- 逻辑是否正确？
- 边界条件是否处理？
- 错误处理是否完善？

### 2. 可读性审查
- 变量命名是否清晰？
- 代码结构是否易于理解？
- 注释是否恰当？

### 3. 性能审查
- 是否存在性能瓶颈？
- 算法选择是否合理？
- 资源使用是否高效？

### 4. 安全性审查
- 是否存在安全漏洞？
- 输入验证是否充分？
- 权限检查是否正确？

### 5. 可维护性审查
- 代码是否易于修改？
- 职责是否单一？
- 耦合度是否合理？

## 审查流程

1. **理解代码目的**
   - 阅读相关文档
   - 理解业务需求
   - 了解上下文

2. **静态分析**
   - 检查代码风格
   - 查找常见问题
   - 验证类型安全

3. **逻辑验证**
   - 跟踪执行路径
   - 验证边界情况
   - 检查异常处理

4. **提供建设性反馈**
   - 指出问题
   - 解释原因
   - 提供改进建议

## 常见问题检查清单

- [ ] 是否有未处理的错误？
- [ ] 是否有资源泄漏？
- [ ] 是否有竞态条件？
- [ ] 是否有硬编码的值？
- [ ] 是否有重复代码？
- [ ] 是否有过长的函数？
- [ ] 是否有复杂的嵌套？

## 输出格式

代码审查结果应包含：

```markdown
## 代码审查报告

### 总体评估
[总体评分和总结]

### 发现的问题
1. **[严重程度]** [问题描述]
   - 位置：[文件名:行号]
   - 原因：[问题原因]
   - 建议：[改进建议]

### 改进建议
1. **[类别]** [建议描述]
   - 当前：[当前实现]
   - 建议：[改进方案]
   - 收益：[预期收益]

### 亮点
- [值得称赞的代码片段]
```

## 注意事项

- 保持反馈建设性
- 解释"为什么"而不仅仅是"是什么"
- 提供具体的改进建议
- 认可好的代码实践
- 尊重作者的设计决策
