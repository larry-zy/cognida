# 数据与知识闭环综合验收

日期：2026-10-16。范围为 `complete-governed-data-loop` 的业务闭环，包含 Supervisor、实际领域执行、标注与固定数据集、特征工程、反馈、策略、数仓及受控 Sandbox。RL、模型训练/部署和独立生产基础设施不在本轮。

## 环境与真实性

前端经真实 Chrome 页面登录专用账号，调用实际 Go API、Python HTTP/gRPC、隔离 MySQL/Redis、真实 Milvus 与模型服务。Playwright 不拦截或替换业务响应，不修改数据库终态，不放松审批与向量来源断言。HTTP 调用用于准备明确 fixture 和交叉核对实际结果。

本次聊天配置为 `deepseek/deepseek-v4-flash`，知识向量配置为 `dashscope/text-embedding-v4`。这些是运行配置中的供应商和模型标识，不代表远端模型权重或供应商内部 revision 已固定。

应用与集成 fixture 使用两个不同数据库，均以 `cognida_review_` 开头。后台 worker 只运行在应用验收库。数据库迁移为 16–35；每一组在隔离库完成 up/down/up，应用不自动建表。共享 Milvus/Neo4j 中仅使用专用测试租户与记录过的知识库，清理不得删除共享集合或原有服务。

数仓实际版本与支持限制见[查询适配器矩阵](../../../docs/implementation/query-adapters.md)，人工质量案例及八格式原始字节生成见[证据矩阵](ACCEPTANCE-2026-10-16-EVIDENCE-MATRIX.md)。本页的流程成功不表示生产数据上的模型准确率。

## 故障与权限验证

核心单元和真实 MySQL/Redis/HTTP 集成覆盖重复键、载荷冲突、租约与 fencing、提交未知、取消传播、重启核对、固定版本、跨租户/用户、源撤权、正文修改、数据源版本和敏感分类变化、旧审批失效以及候选禁止被正式检索消费。

Sandbox 另用实际 Docker 验证越目录、链接/归档/输出验证、禁网、CPU/内存/进程/时间/磁盘限制、取消和资源回收。只验收 `controlled_development`，普通 Docker 不构成多租户不可信代码的强隔离证明。

后续综合回归发现已运行Sandbox取消时，历史`launch_committed`阶段被误判为新的执行推进；容器虽已移除，取消终态仍被重复拒绝。修复允许确认清理且无产物的取消/失败/超时保存，仍拒绝旧租约、取消后的成功发布和过期执行。实际旧记录由重启后的正常worker自动恢复为cancelled，没有手工修改数据库，见[前后回执](evidence/2026-10-16-sandbox-cancel-recovery.json)。页面用例现要求先确认running再取消，原30秒取消确认和零产物要求保留。同轮重规划测试将合法的一致性读取409误当失败，现仅在原20秒轮询内重读，不重放写操作。该轮35通过、2失败保留在历史中。

研究将首轮有效审查固定为历史快照。可选补充审查失败时，只在快照、逐字引用与当前来源权限全部复核通过后保存部分报告；当前支持结论降为待核实，冲突保留，新增未审来源单独显示。首轮审查失败、取消、超时和撤权不能产生可用报告。

可解析 JSON 的必填字段、数量、未知字段或缺少必需引用标记/引文数组，允许一次显式结构修复；全部已有引用仍须先通过安全核验，修复结果须再次通过完整引用校验和独立语义审查。调用前持久记录“修复＋审查”两个预留名额，取消时不发送请求；模型调用仍不超过4次、含检索的逻辑调用总数不超过20、总期限仍为120秒，名额用完则停止补充检索。截断、非法JSON、供应商/网络失败、伪造引用不触发该修复；修复仍无效时明确失败，不把无效初稿作为可用部分报告。诊断不含模型正文或推理；重启不自动重放付费调用。

Supervisor 的规划调用显式使用请求级有界 JSON 选项，只对已验证的 provider/model 组合启用供应商参数；正常聊天不受影响。规划仍限一次调用、45秒、4096输出token；截断即使是合法JSON也被拒绝，只返回固定错误码、允许的结束原因与数字诊断，不返回模型原文。真实MySQL＋HTTP模型fixture验证失败不会生成计划、子任务或投递，撤权后不再调用模型。历史一次502只有通用结构错误记录，不能追认具体供应商失败原因。

另一次综合回归为36通过、1失败：研究初稿包含摘要、分析与4条发现，却漏掉必需的引用标记，校验器以`draft_citations_missing`拒绝，未产生报告产物，见[脱敏诊断](evidence/2026-10-16-research-citation-diagnostic.json)。该遗漏接入上述一次结构修复；修复前遍历所有已有引用，任何未知来源或非逐字匹配引文仍直接拒绝。模型须重新依据同一来源补足引用，完整校验和独立审查不变，页面断言不放宽。

候选计划中的汇总预算由控制器按各节点及其重试次数确定性核算，最多补足总尝试数、总调用数、总成本和总时限，并返回调整前后值与原因。原始预算和补足后的预算都不得超过任务授权上限；节点、重试、工具权限、最大节点数和并发保持不变。结果仍须通过完整计划校验并由用户显式保存；直接提交计划不做该补足。真实MySQL/HTTP回归覆盖上限拒绝、撤权、候选零写入及确切计划的CAS保存。

公网 API 验收发现 HTTPS 多地址连接的恢复缺口：旧实现只在 TCP 失败时尝试下一地址。无凭据逐地址探测复现了一个地址 TCP 成功但 TLS 超时、另一地址握手成功。修复将 DNS、TCP 与证书校验放入总计10秒的连接预算，各地址最多3秒且共享剩余时间；全部地址须先通过安全校验，只在发送 HTTP 请求前回退，不重放请求。真实 TLS＋MySQL＋HTTP 测试验证了两页仅发送两次请求、失败连接关闭、取消和私网拒绝，见[脱敏诊断](evidence/2026-10-16-api-transport.json)。历史失败只保留脱敏通用错误，不能据此追认其确切网络阶段。

一次综合回归为36通过、1失败：复用的测试知识库已累计21份完全相同的网页文本，Top20均为真实Milvus结果且得分为1，新文档未进入前20。只读核验确认该次七阶段成功且新文档的真实向量存在，见[隔离诊断](evidence/2026-10-16-retrieval-isolation.json)。后续完整回归使用新建的空发布知识库，固定来源和研究样本库独立保留；没有提高TopK、延长60秒上限或接受旧文档来替代本轮文档。

后续一轮为34通过、3失败：公网JSON请求失败、Supervisor候选400、总览混合列表前12项挤出了处理流程链接。公网请求的历史阶段未知；随后一次生产FetchJSON探测HTTP200且只发送一次GET，见[网络回执](evidence/2026-10-16-public-network.json)。API页面验收现显式配置3次请求预算，只允许同一任务、同一配置与截止时间、零页面/记录/字节/产物且`retryable=true`的partial通过真实UI继续，最多两次；每次请求和恢复均保留回执，整段共享原140秒观察上限，预算耗尽仍失败，最终数据、审批和报告断言保持。该恢复依据产品回执，不声称已识别历史错误为瞬时网络。

Supervisor随后一次独立生成返回有效候选、任务仍draft且无计划或子任务，见[独立诊断](evidence/2026-10-16-supervisor-diagnostic.json)；没有据此追认历史400原因或修改校验器。E2E现在在断言前附脱敏响应。总览增加任务类型筛选，在前12条展示限制之前筛选已读记录；切换租户重置选择，原报告深链和零写入断言保留。

BigQuery 已实现服务账号引用、固定project/dataset/location、dry-run、扫描预算、持久作业、恢复/取消/分页和精确类型。本地 REST 协议 fixture 加真实 MySQL 持久作业、对象资产与分析计算验证了消费者接线，**没有真实GCP项目和计费执行证据**。该外部验收保留未验收，不能合并进六引擎通过率。

特征 embedding 的版本校验、持久任务与结果复用已由固定向量端口及真实 MySQL 验证；本轮没有平台可信的 `EMBEDDING_REVISION`，页面验证的是不可用说明和拒绝行为，**未验收固定 revision 的真实模型特征物化**。知识发布使用真实 embedding 并通过 Milvus 检索，两者的证据分别计量。
