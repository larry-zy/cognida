# Hugging Face 实测：数据处理、标注、特征与漂移

本轮直接下载固定 revision 的公开数据，经过实际生产代码、独立 MySQL、Redis、Python HTTP、Go HTTP 和已配置模型供应商测量。**确定性处理正确，不等于自动标注达到生产质量，也不等于系统已完成生产容量验收。**

## 数据与实验边界

| 数据 | 原始 train / test 或总量 | 本轮用途 |
| --- | ---: | --- |
| BANKING77 | 10,003 / 3,080，77 类 | 英文清洗保真、全量规则分类、154 条模型分类 |
| MASSIVE zh-CN | 11,514 / 2,974，60 类 schema | 中文清洗保真、全量规则分类、117 条模型分类 |
| Few-NERD supervised | 131,767 / 37,648，8 粗类 | 全量实体规则、64 条模型实体标注 |
| Wine Quality | red 1,599＋white 4,898，共 6,497 | 精确特征、窗口、增量/回填及漂移控制实验 |

下载 13 个文件共 23,993,866 bytes。所有 revision 和原文件 SHA256 在数据锁中，转换不执行远端 Python。来源、原始与镜像许可分别保留在协议中。Few-NERD 按 token 间单空格重建文本，按粗粒度连续 IO 标签构造 span，不能恢复原文空白或相邻同类隐藏边界。

中文官方 test 缺一个类别、另一个只有 1 条；在零模型调用时将每类采样固定为 `min(2,test样本量)`，没有从训练集补题。跨 split 同正文的 unique text 数为 MASSIVE 187、Few-NERD 3,549；按 test 行计分别为 223、3,599。报告同时保留全官方 test、unseen text 和 overlap 指标，不删除困难或重合记录以抬高分数。

## 采集、质检与清洗

27,571 条中英文原始记录在 TestClient 和真实 HTTP 各执行 112 次请求。真实 HTTP 累计 18.785 秒；每批最多 2,000 原始行。全部原字段、类型、顺序、来源行映射与重复执行结果核对通过；人工复制行、空行和派生字段首尾空白另有独立 oracle，误删、漏删及意外改值均为 0。

原数据的 545 条自然重复文本和 12 条原始边缘空白均保留。源记录 ID 区分合法重复正文；该结果不表示自动识别了所有自然业务脏数据。没有测自然脱敏召回率、复杂跨批近重复或语义纠错率。

另用固定 512 条官方 test 记录走 **Go TCP API→真实 MySQL＋Redis claim/ack→带内部认证的 Python HTTP→不可变结果资产**。质检、清洗、幂等、来源不可变、跨租户拒读均通过；8 条控制记录验证大整数、布尔/数值区分和带类型的 DECIMAL 字符串。授权身份为显式 fixture，未把它称为真实登录或浏览器 E2E。

发现并修复了实际丢数据问题：Pandas 默认比较将 `true/1/1.0`、`false/0/0.0` 当成重复，诊断却按 JSON 类型说没有重复。旧代码在 10 行混合类型控制中误删 4 行；现在按类型编码去重键，再投影原始值，误删为 0。**裸 JSON 小数的任意精度并未被承诺**；精确 DECIMAL 仍需字符串＋`column_types` 合同。

## 自动标注与固定数据集

模型使用受管配置 `deepseek-v4-flash`，20 秒 deadline、4096 output tokens、并发 2，每条只调用一次。供应商返回 usage 可记录，但未返回真实货币费用，`cost_usd=null`。

全量规则成绩如下，模型成绩与其分开统计：

| 规则任务 | 官方 test 分母 | Accuracy | Macro-F1 | Micro-F1 | matched 覆盖率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| BANKING77 分类 | 3,080 | 32.14% | 42.69% | 47.55% | 35.19% |
| MASSIVE 中文分类 | 2,974 | 19.50% | 35.53% | 30.08% | 29.69% |
| Few-NERD 实体 | 37,648 | 不适用 | 8.05% | 11.06% | 27.24% |

规则只从 train 生成，未看 test 选关键词；分类多命中作为弃权。低覆盖的关键词/词典规则适合辅助建议，不能直接承担通用自动标注。实体按 `(type,start,end)` 精确计分，合法 uncertain span 仍进入 F1，覆盖率单列。

第一轮 335 条模型结果完整保留：英文分类 146/154、中文分类 92/117、实体 56/64 被严格输出合同拒绝；无执行、供应商不可用或超时错误。全分母英文/中文 accuracy 分别为 3.25% / 12.82%，实体 micro-F1 为 1.27%。这是真实服务整体可用性成绩，不能只拿少量合法预测的 precision 宣称模型质量很好。

用**独立训练集前 6＋6 条**补充诊断，未重试 heldout：英文 6 条均存在原文字面片段但模型算错字符位置；另有分类返回非空 tags/category 的分支混用。原始响应仅在本机 0600 文件中保存用于诊断，仓库只留诊断计数、样本 ID 和摘要。

修复输出合同后，模型按任务类型只返回对应分支；省略 start/end 时，服务端仅在原文片段**精确且唯一**时派生 Unicode 位置，再走既有校验。重复、虚构、null、单边或错误显式位置继续拒绝，不丢弃非法分支“修成成功”。离线回放旧 12 响应仍为 8 拒绝、4 合法；另注册同 12 条训练样本的新请求变为 1 拒绝、11 合法，唯一失败仍是不精确字面片段。

`v3` 冻结新代码与 prompt 后，对同一批 335 条样本各调用一次，未重抽或择优重试：

| 模型任务 | 固定样本数 | 修复前 → 后 Accuracy | 修复前 → 后 Micro-F1 | 后 Macro-F1 | 后 matched 覆盖率 | 合同拒绝数前 → 后 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| BANKING77 分类 | 154 | 3.25% → **72.08%** | 6.25% → 72.79% | 71.49% | 98.05% | 146 → 0 |
| MASSIVE 中文分类 | 117 | 12.82% → **79.49%** | 21.43% → 81.22% | 78.79% | 95.73% | 92 → 0 |
| Few-NERD 实体 | 64 | 不适用 | 1.27% → **54.93%** | 48.04% | 67.19% | 56 → 9 |

修复后仍有英文 3 条、中文 5 条弃权；实体 21 条未标为 matched，其中 9 条合同失败。合法 uncertain 实体片段仍进入精确 F1。各任务执行错误为 0；P95 service latency 分别约 1.90 / 1.50 / 1.58 秒。中文全 schema Macro-F1 保留缺样本的第 60 类；仅有 gold 支持的类别 Macro-F1 为 80.12%。不能用合法输出率替代语义准确率，也不能将 9 条未合法输出的实体样本排除在分母之外。由于 heldout 未保存原模型正文，本轮未对这 9 条逐条追认具体字段根因。

这次 `v3` 是已观察测试集上的工程修复回归，**不是一份全新的泛化证据**。公开数据也可能出现在模型预训练中。规则全量 test 与模型子集分母不同，不能直接把其分数差当严格提升；证据中另保留相同模型样本上的离线规则配对结果。当前准确率仍不足以批准无人审核发布。

调用与成本记录：两轮模型各 335 次，加前后训练诊断各 12 次，共 **694 次**。供应商报告 prompt 965,049、completion 69,201，共 **1,034,250 tokens**；未提供真实货币费用，费用保持 null，不用估价代替账单。

数据集机制单独用明确的人工正确标签 fixture 验证：三份数据各 3 条，真实 HTTP/MySQL 执行预标注、人工修订审核、不可变发布、幂等重放、后续编辑不改已发布版本、其他用户与源撤权拒读。全部通过，**这些人工 oracle 结果不进入自动标注准确率**。

## 特征正确性与容量

Wine 原始十进制字面值保留，HTTP 输入以 `json.Number` 传递，全部物化值与独立 `big.Rat` 精确计算比对。ID、实体、事件时间为人工测试元数据；不声称 Wine 自带业务时序。

| 场景 | 实际结果 |
| --- | --- |
| 5,000 行全量物化 | 5 分区，1.330 秒；逐值一致 |
| 扩到 6,497 行的增量 | 新增 1,497 行，执行 1.070 秒；全量逐实体 HTTP 批查询校验 9.222 秒 |
| 32 行修正回填与撤回 | 回填执行 0.654 秒；撤回、修正前/中/后历史和水位另经核验一致 |
| 5 类窗口聚合 | sum/mean/min/max/count；240 行输入形成 239 个唯一实体时间键，各结果和边界一致 |
| 10,000 行压力边界 | 由 6,497 原行重复扩展，7 列投影、10 分区，3.875 秒；10,001 行明确拒绝 |
| 源授权撤回 | 查询与再物化返回 403，已提交回执保留；fixture 授权撤回，非外部身份提供商验收 |

当前单次同步物化最多 1,000 行，durable job 输入最多 10,000 行，输入总单元格最多 100,000，单次实体×特征查询最多 1,000。以上为本机有界正确性及容量检查，不是生产并发吞吐/SLA，也未验证特征对下游预测质量的增益。固定 revision 的 embedding 模型仍未实测。

## 漂移

预先固定 seed=20261016、effect threshold=0.2、最低样本 20、最多采样 1,000。数值使用经验 KS 距离，类别用 total variation，缺失率单独比较；距离不是 p 值或漂移概率。

- 20 个与参考集及彼此均不重叠的稳定混合窗口，告警 **0/20**；最大 effect 为 0.119。
- 11 个明确人工干预窗口，检出 **9/11**。alcohol +0.1/+0.25 的 KS 为 0.057/0.13，未达阈值；+0.5 的 KS 为 0.201，首次告警。从首次非零偏移算延迟为 2 个窗口。
- 原样/置换零距离、突变、缺失、schema 变更与独立 CDF/频数 oracle 一致。red/white 群组差异仅称群组差异，不冒充天然漂移事件真值。
- 固定 `CurrentRefID` 监控两轮复用了相同报告，新建未选择的快照不会自动进入监控。真实上游刷新连接器未在本实验配置或验收。

0/20 与 9/11 都是该控制实验的有限分母，不能外推为真实业务误报/漏报保证。真实投产需业务时间序列、可追溯事件标记、分群阈值与持续新批次接入。

## 验证、清理与生产结论

- 最终 Go 核心全量：101 个有测试包通过，0 失败；Python 全量 689 通过、3 跳过（真实分析供应商 opt-in、图像/Milvus opt-in、Python Playwright Chromium 未安装）。跳过项不计为验收通过。
- 数据锁与转换边界 4 项单测通过；Go/Python 采集真实接口及 race 通过；特征/漂移 5 项普通与 race 通过（23.702 / 98.208 秒）。清洗 47 项定向核心/API测试包含在 Python 全量回归中。
- 标签治理整包 race 通过（最终留存 2.246 秒）；新合同真实 MySQL＋TCP provider/API 回归通过（2.668 秒）；旧 12 响应离线回放通过（1.849 秒，错误断言仍被拒绝）。持久幂等、失败不改样本、成功建议仍 pending、未审核不能发布均核验。
- 独立 Review 覆盖生产修复、benchmark oracle、指标、协议、证据与文档；发现的数据锁绕过和窗口完整键集缺口已补回归。最终两轮模型样本、规则摘要相同，`v3` 的 8 份测量代码摘要与最终源码一致。
- 此轮没有重跑浏览器 E2E；此前 37/37 的页面验收仍按原日期单独记录，不能与本轮统计合并。
- 测试 Python 进程、专用 MySQL/Redis、2 个匿名卷及临时凭据已清理，62501/62502/62510 均释放。删除指令只针对已核标签的本任务 ID。原快照 19 个非任务容器中 17 个状态一致、2 个在结束时已不存在，差异如实保存在[清理回执](results/2026-10-16/cleanup.json)，本次清理没有操作这两个 ID。

可以将确定性采集清洗和有界特征计算用于有人工复核的小范围试运行；不应据此批准无人审核的通用自动标注或全量数据平台投产。仍需要真实中文实体/关系与业务标注集、自然脏数据与复杂文件质量、真实持续上游、租户生产认证、峰值并发与长期恢复验收。BigQuery 外部环境、可信固定 revision 的 embedding、多租户强隔离与生产运维仍是独立未验收范围。RL 按用户要求另行规划。
