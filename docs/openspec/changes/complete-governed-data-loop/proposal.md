## Why

Cognida 已具备采集、不可变资产、清洗、规则打标与审核、知识发布、分析和评测等模块，但跨模块任务、审核产物消费、数据集版本及评测返工尚未形成完整闭环。README 又混用了历史状态和产品愿景，需要以当前代码与验收证据重新界定范围。

本提案对应用户确认的第 1 组「业务闭环」和第 2 组「能力补全」。2026-10-15 调研与 README 更新后，现已开始任务控制、计划预检、持久化和 Runner 契约等基础实施；完成状态须由实施任务的测试与 Review 证据确认，不能把草稿 API 或预检通过当作完整执行闭环。最终目标架构中的受治理策略进化与数仓建模也纳入本变更。Agentic RL、模型训练／微调、模型部署，以及 K8s／Helm 等独立生产化工程继续延后。

## What Changes

- 增加 Supervisor 与跨域持久化任务控制，复用 lifecycle、collection、governance、evaluation 的现有执行器；保留各领域状态真源。
- 在工具执行层增加隔离 Sandbox，承接自定义清洗和派生脚本，隔离产物经正常质检与审批发布。
- 将现有清洗专家升级为诊断、方案、预览、执行和复检流程；增加知识分类与训练／评测样本两类 Agent，审核后分别进入知识元数据和版本化数据集。
- 接通固定基线评测、反馈定位、返工、比较、发布与撤回；贯通来源更新、删除和权限变化对派生产物的影响。
- 复用经验蒸馏、Skill 与 Playbook，将候选经验、技能、检索参数、规则和编排策略纳入不可变版本、隔离评测、审核激活、运行快照及监测回退，不通过策略更新扩大权限。
- **BREAKING:** 旧采集入口的新建／再次运行统一接入候选与发布审批，历史已提交回执保留；不再通过兼容入口绕过正式发布门禁。
- 按明确支持矩阵扩展 Web／API／文件／库表接入与 ClickHouse、Doris、StarRocks、Hive、BigQuery 只读分析；每个引擎独立验收。
- 复用语义模型、指标和血缘，增加数仓建模 Agent 的主题域、事实粒度、维度及原始／明细／汇总／应用层转换计划，贯通有界 DAG、增量水位、回填和变更影响；加工只落授权受管派生空间。
- 扩展现有字段特征为可重现的变换、聚合和物化，接通真实基线漂移检测与治理任务。
- 加强 DeepResearch 的主张—证据关系、来源冲突与补充调查；增加与默认分析入口分离的受控写入／ETL 工作流。
- 沿用现有界面风格，扩展任务详情、清洗差异、标注、数据集、评测比较、特征监控与操作审核页面。
- 更新 README 的已实现、有限实现、规划和延期状态，验收证据只覆盖实际执行过的场景。

## Capabilities

### New Capabilities

- `governed-task-control`: 跨域目标规划、受约束的任务计划、持久化子任务协调、审批与恢复。
- `sandboxed-tool-execution`: 受限执行环境、输入输出契约、资源预算、取消回收和产物隔离。
- `governed-data-preparation`: 清洗诊断、两类标签方案与标注、人工复核和审核产物消费。
- `quality-feedback-loop`: 固定基线比较、返工与版本发布、变更传播和闭环证据。
- `source-ingestion-contracts`: 分来源采集、快照、增量水位、鉴权和失效传播契约。
- `warehouse-query-adapters`: 数仓能力描述、方言与类型适配、只读查询和真实引擎验收。
- `feature-materialization-monitoring`: 版本化特征变换、时点物化、真实基线漂移监控。
- `research-evidence-review`: 主张与证据支持检查、来源冲突、预算内继续研究。
- `governed-operation-jobs`: 独立受控写入／ETL 任务、绑定操作内容的确认、提交恢复与补偿。
- `governed-strategy-evolution`: 经验／Skill／执行策略候选版本、固定基线评测、审核发布、运行快照与监测回退。
- `warehouse-modeling-workflows`: 数仓主题域和事实／维度建模、分层转换 DAG、增量回填与血缘影响审核。

### Modified Capabilities

- `evaluation-dataset`: 增加审核样本发布的不可变数据集版本，评测运行固定样本与配置，不改变已有文件／数据库数据集兼容入口。

## Impact

- Go：在现有 model/service/repository 分层扩展任务、数据集版本、发布记录、策略快照、数仓模型／加工计划、特征与监控；新增表结构使用成对版本迁移，编号在实施时按 main 当前最大值分配。
- Python：复用现有质量、清洗、增强、analytics 计算；修正漂移统计方法，新增受限特征算子。脚本执行与共享计算服务分离。
- Web：复用工作总览、流水线／专家、治理工作台、语义模型／血缘、数据源和研究／评测页面；新增跨域任务详情、数据集版本和操作审核入口，并扩展策略版本评审、分层加工计划及影响预览。
- 外部依赖：独立 Sandbox runner、真实数仓验收环境；云账号、Hive 鉴权和各引擎版本是接入验收前置条件，未具备时保持未验收。
- 兼容性：原有 Agent ID、流水线模板和历史记录继续可读；默认分析只读、私人记忆隔离和原始资产不可覆盖约束不放宽。
