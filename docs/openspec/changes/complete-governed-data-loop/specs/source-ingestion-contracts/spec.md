## ADDED Requirements

### Requirement: 分来源能力与授权契约
系统 SHALL 为 Web、认证 HTTP API、文件和库表分别登记格式、鉴权、分页、快照、限额及删除检测能力；MUST 在采集和读取产物时校验当前租户、用户及来源权限，不得将已实现的单一来源流程等同于全部来源支持。

#### Scenario: 请求不可访问或未支持的来源
- **WHEN** 用户提交其他租户的来源句柄，或选择尚未支持的协议或文件格式
- **THEN** 系统明确拒绝或报告能力不可用，不泄露来源内容，不创建成功的采集产物

### Requirement: 认证 API 的有界分页
认证 API 接入 SHALL 先支持 GET 与 JSON 的分页或游标模式，凭据仅使用受管引用；MUST 限制页数、记录数、字节数和总时长，并复用公网地址、重定向、凭据目标绑定及域名限速规则，不得把凭据写入日志、任务参数展示或产物。

#### Scenario: 分页采集中断或达到预算
- **WHEN** 后续页面鉴权失败、请求超时或达到读取上限
- **THEN** 系统记录已读取范围、失败原因和可恢复检查点，保持未完成或部分完成状态，不把截断结果声明为完整快照

### Requirement: 快照与增量水位
每次采集 SHALL 固定来源配置版本、读取范围和快照标识，记录来源提供的一致性保证；增量任务 MUST 保存稳定记录键、去重依据和水位，只有产物与检查点持久化成功后才能推进水位，不得在重试时混合无法证明属于同一快照的页面。

#### Scenario: 游标过期后重新获取来源
- **WHEN** 任务恢复时原快照游标已失效，来源无法继续一致性读取
- **THEN** 系统保留旧任务范围和失败证据，显式创建新的快照尝试并按稳定键去重，不将新旧页面合并成完整成功

### Requirement: 候选产物与幂等发布交接
采集 SHALL 保留原件摘要、解析器版本、逐项结果和来源引用；新统一任务 MUST 只交付候选产物，质量检查和审批完成前不得在正式知识检索中可见。旧直接入库路径的新建与重跑 MUST 迁移至统一发布授权，已提交历史回执保留；重试依据确定性操作标识核对产物，不重复入库或创建发布版本。

#### Scenario: 候选交付与旧入库任务恢复
- **WHEN** 新统一任务生成采集产物，或旧直接入库任务在提交后丢失回执并重启
- **THEN** 新产物保持候选且审批前正式检索不可见；旧任务核对并绑定已有历史回执，不重复入库，其新建和重跑另走当前统一发布授权

### Requirement: 来源失效传播
来源删除、禁用或权限撤销 MUST 先阻断受影响内容的读取，再通过可重试事件更新派生资产、索引和缓存；不支持删除检测的连接器 SHALL 明示限制，历史记录保留失效原因，不得因恢复旧版本重新暴露已撤权来源。

#### Scenario: 已发布来源被撤权
- **WHEN** 已进入知识检索或分析报告的来源失去读取权限
- **THEN** 新读取立即拒绝该内容，后台清理可重试且保留审计关联，报告标记证据失效，版本回退不能恢复访问
