## ADDED Requirements

### Requirement: 受约束且可审阅的任务计划
Supervisor SHALL 仅从能力注册表生成有节点数、总预算和重试上限的无环计划；每个节点 MUST 声明输入输出、工具、权限和依赖，控制器在执行前校验身份、引用授权与计划版本并保存快照。

#### Scenario: 合法计划进入执行
- **WHEN** 用户提供完整目标和可访问输入，计划通过结构、能力、权限与预算校验
- **THEN** 系统保存可审阅的计划及预算，由控制器调用已有领域执行器，并关联真实领域任务 ID

#### Scenario: 缺少输入或计划越界
- **WHEN** 计划缺少必要输入、包含未知能力、依赖环、未授权引用或超出预算
- **THEN** 系统返回具体待补信息或拒绝原因，不提交任何领域子任务

### Requirement: 父子任务幂等绑定与恢复
控制器 MUST 持久化父任务、计划版本、确定性幂等键和领域任务绑定，以事务投递记录及恢复扫描解决中断；领域执行器 SHALL 保持其状态真源，回调与轮询必须核对身份、版本和 attempt。

#### Scenario: 重复提交或投递中断后恢复
- **WHEN** 相同作用域与幂等键被重复提交，或子任务已创建但父任务绑定尚未确认时进程重启
- **THEN** 系统查回并绑定同一领域任务，继续核对状态，不重复采集、生成资产或发布

#### Scenario: 迟到结果不能覆盖取消
- **WHEN** 已取消任务或旧 attempt 收到成功回调
- **THEN** 控制器不以迟到回调重启后继节点或覆盖父任务终态，但核对并保留真实提交回执，不因取消而声称已发生的副作用不存在

### Requirement: 重规划与审批绑定
系统 SHALL 为重规划生成新版本，仅替换尚未执行节点；审批 MUST 绑定计划与操作内容，目标、权限或写入范围变化使相关旧审批失效，Supervisor 不得自行批准。

#### Scenario: 重规划扩大发布范围
- **WHEN** 新计划修改发布目标或所需权限
- **THEN** 系统保留已执行结果与旧计划证据，将受影响节点置为待审批，重新校验授权后才允许执行

### Requirement: 总预算取消与真实汇总
父任务 MUST 限制累计耗时、调用量、成本和重试次数，并将取消传播到领域任务；状态 SHALL 区分待审核、部分完成、失败、超时、取消及结果待核对。取消不得抹去已提交的发布或写入回执；提交未知时 MUST 保持 cancel_requested／待核对并按确定性操作 ID 对账，禁止盲目重放。

#### Scenario: 执行中耗尽预算
- **WHEN** 仍有节点未完成时总预算耗尽或用户取消父任务
- **THEN** 系统停止新投递并请求终止在途任务，保留已完成产物与真实副作用回执；已提交但结果未知的操作保持待核对直至对账，不把停止推进等同于副作用未发生
