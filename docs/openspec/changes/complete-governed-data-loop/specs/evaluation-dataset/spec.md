## ADDED Requirements

### Requirement: 审核样本的不可变数据集版本
系统 SHALL 在逻辑 dataset_id 下发布不可变版本，以 manifest 固定样本 ID 与摘要、来源版本、标签方案、审核版本和划分策略，复用既有样本及资产存储；MUST 仅发布获准样本，在读取、执行及恢复时重查 tenant、user 与来源有效性，不可变内容不代表永久授权。本要求不移除现有文件与数据库入口。

#### Scenario: 发布审核样本版本
- **WHEN** 授权用户发布全部通过审核与格式校验的样本集合
- **THEN** 系统返回稳定版本 ID 与内容摘要，重复发布使用幂等回执，后续草稿修改不改变该版本

#### Scenario: 未审核或失去权限的样本
- **WHEN** 发布集合含未获准样本，或读取、启动及恢复固定版本时来源被删除、撤权或访问作用域不符
- **THEN** 系统拒绝相关操作并指出不可用引用，标记受影响历史结果失效，不静默排除样本、不泄露受保护正文或回退到可变数据集

### Requirement: 评测固定数据集及完整配置
评测创建时 MUST 固定具体数据集版本、目标配置、提示词与模型标识、检索参数及 grader 版本；运行和重试 SHALL 读取该快照，并在结果展示实际版本，不在执行中重新读取可变 latest。

#### Scenario: 运行期间修改数据集草稿
- **WHEN** 评测已创建后用户新增、修改或删除当前草稿样本，或更新默认评测配置
- **THEN** 既有评测及其重试仍使用创建时的样本与配置快照，新评测才使用重新选择并固定的版本

#### Scenario: 兼容旧 dataset_id 请求
- **WHEN** 旧客户端从既有文件或数据库入口仅提交 dataset_id
- **THEN** 系统按原有解析及格式校验规则加载数据，在创建评测时生成并绑定固定快照，保留已完成历史评测记录

### Requirement: 可复现划分与泄漏检查
数据集发布 MUST 固定来源组、时间边界、划分算法及随机种子（若使用），对训练、验证和测试集合执行重复及近重复泄漏检查；不适用的划分 SHALL 明确声明，本范围不执行训练。

#### Scenario: 来源或近重复样本跨集合泄漏
- **WHEN** 划分结果违反已登记的来源分组、时间规则或重复检测门槛
- **THEN** 系统阻止版本发布并输出冲突证据，同一输入与固定配置重新计算得到相同划分及检查结果

### Requirement: 显式评测 profile 与样本映射
数据集 MUST 显式声明消费 profile 并校验映射：QA 包含 question／reference_answer；RAG 增加已授权来源与相关 chunk；Agent 增加 expected_tools／expected_steps；SQL 包含 datasource／dialect／gold_sql 且执行只读。classification、named_entity、relation SHALL 仅在存在已登记的兼容映射时供对应消费者使用，不得直接冒充 QAPair。

#### Scenario: 不支持的样本与评测组合
- **WHEN** 发布请求缺少目标 profile 必需字段、映射不存在、RAG 来源未授权，或 SQL 样本包含写操作
- **THEN** 系统在版本发布前拒绝并返回字段或组合错误，不自动猜测答案、不将通用标签转为问答样本，也不执行 gold_sql 写操作
