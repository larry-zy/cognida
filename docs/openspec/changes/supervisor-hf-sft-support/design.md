## Context

TaskControl 已有不可变计划、预算预留、outbox、租约、重启核对和独立 ExecutionAdapter 合同。HF 有同步有界导入与固定来源回执，SFT 有 prepared/标准绑定和审核导出。扩展应重用这些领域真源，避免把普通工具响应当作持久任务。

## Goals / Non-Goals

**Goals:** HF/SFT 成为真实可执行节点；独立入口行为保持；取消和崩溃均有确定持久语义；技术支持场景覆盖既有答案到 SFT、知识到检索和 Agent 回答。

**Non-Goals:** 合成缺失答案、自动批准、模型训练/RL、生产部署、任意远程脚本、无界采集。

## Decisions

- HF capability 为 `huggingface.import`，闭合参数 `{huggingface:{request:...}}`，0 输入、raw_asset 输出、固定 SHA、1 次尝试、11 次逻辑调用、最多120秒。领域表加 governed/claim 状态，Submit 原子落 queued，独立 worker 一次 claim；未知运行不重放下载，真实 deadline 到期失败。取消与提交共享唯一键栅栏。沿用既有安全 fetch/decoder/asset 服务，不建立另一套采集器。
- SFT capability 为 `governance.sft`，闭合参数 `{sft:{name,standard_version_id,format,columns}}`，一个真实 prepared cleaned_asset 输入、Result manifest 输出，3 次逻辑调用、120秒、一次尝试。使用已有 governance_records/worker 的固定 profile；稳定候选 ID、候选与完成回执原子提交，审核/发布是后续独立人工操作。
- Supervisor 有可执行无输入采集能力时可以在没有已有资产的条件下澄清与规划。固定 repo/SHA/文件/映射/标准仍须用户明确输入并由 adapter 验证；不得从模型猜测身份、凭据或授权。
- UI 以能力目录与类型化表单形成可审阅四节点模板，保留模型规划入口并做真实模型提案验收。结果链接恢复领域真实记录，不自动提交动作。
- 场景使用固定公开技术支持数据小样本；SFT 仅保留其已有答案，不能当作训练效果。知识问答另以来源内容、检索回执与引用验证实际可用性。所有测试写入隔离数据库/账户/知识库。

## Risks / Trade-offs

- HF 进程在 claim 后崩溃会等待截止，不能自动续传 → 明确呈现未知/超时，保持一次下载语义，允许人工新操作。
- 公共问答存在过时或不可信答案 → 数据卡/commit/hash、人工审核和知识引用保留，报告不声明业务质量或生产批准。
- 父任务成功只表示候选构建完成 → 摘要和页面明确 `review_required`，不修改人工权限。
- 外部网络/模型不稳定 → 固定输入、明确真实失败、保留证据，修复原因后才重跑；不替换响应或跳过断言。

## Migration Plan

通过正式 migration 38 应用 HF 持久编排列，部署匹配 worker 与 TaskControl 注册。回滚先停止新调度并排空/取消本轮任务，再按正式 down 回滚；不自动修改生产 schema。

## 场景衔接补充

真实 TechQA 文件把知识资料存为 `contexts` 对象数组。准备能力新增显式 `text_projection`，仅选定正文成员进入知识正文，其他问答列不会混入；保留来源行身份和文档序号，任何空资料或畸形文档整批拒绝。资料行、文档总数与最终正文均有界。该操作仍可独立调用。

审核标签在资料发布前产生，应用到新知识文档时需要真实发布桥。`publication_ref_id` 必须来自当前用户已人工审批且成功的 data-asset 阶段，其输入父链包含被审核来源，stage 输出、不可变发布资产与知识入库回执一致。原文摘要和入库时分块摘要分别固定，避免分块换行或重叠误触发原文一致性检查。MySQL 最终事务同时核对审核版本、当前 KB 权限、文档原始 FileHash、历史入库摘要及当前有效分块摘要；编辑正文后标签自动失效。

迁移 39 给 knowledge 增加 `ingested_chunk_digest`，旧行保留空值，禁止把当前内容回填成历史证明。processor 在完成时只原子更新自身字段，幂等重放返回历史摘要；普通文件上传的文件元数据不当作已核验的原始字节证据，重处理先失效旧摘要。

数据卡标称 908 行，但固定 train.json 实际含 910 行，记录实际解析事实。验收正向使用前两条可答样本；第三条实际是 `answer="-"`、`is_impossible=true`、`contexts=[]`，不能冒充空白答案。真实负例验证空资料投影失败；SFT 空白答案拒绝由单独的合成边界样本验证。通用 SFT 结构校验不自动判断业务答案正确性。

## 页面验收发现的通用合同修复

- 零输入采集节点不能复用输入数量校验来决定输出可见性。引入可选 `ExecutionOutputAuthorizer`，HF 输出单独核验实际资产及已完成导入的所有者、回执、清单和当前凭据；任务收尾与摘要读取仍经过生命周期 resolver 二次授权。旧 adapter 保留既有输出来源校验。
- 真实模型曾遗漏输入解析的调用预留。控制器在未保存候选中按授权能力的 `base_calls + calls_per_input × input_count` 补齐节点调用数，显示逐节点 `budget_adjustments`，再计入所有尝试的总预算。原始任务预算不扩大，业务参数、来源、尝试次数及执行时限不改变。直接保存计划则严格拒绝不足的调用预留或超出 profile 的时限；修正后的候选仍需人工显式保存和启动。
- 知识助手列表缓存按用户 ID、工作空间 ID、认证状态分别监听，避免同身份资料对象刷新误清空在途列表；真实身份切换仍同步失效。Agent 流式请求与其他 HTTP 请求统一使用同源 `/api/v1`，开发环境经 Vite 的显式代理连接当前后端，避免旧 `.env` 地址绕过代理连接另一服务。
- 流式助手回答的消息 ID 使用完整 36 字符 UUID，与正式 `messages.id` 字段匹配；不再额外加前缀导致插入失败。SSE `done` 仍在实际持久化后发送，并保留 `persistence_failed` 的真实状态；测试同时核验回答、检索工具回执和会话计数落库。
- 共享 SSE 响应显式声明 `text/event-stream; charset=utf-8`，与 JSON 输出字节及浏览器 TextDecoder 一致，避免调试/测试客户端按其他字符集读取。页面验收继续逐字比较真实 SSE 答案与会话 GET 的持久正文，不修补字符或放宽断言。
- SFT 执行回执、构建表单与当前样本共用右侧详情栏；切换到其他数据集时清除旧执行回执，同一数据集刷新保留匹配回执。客户端 generation/身份失效保护不变，避免任务来源与当前样本错配。
