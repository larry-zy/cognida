# Cognida 应用场景与落地背景

本文档介绍 Cognida AI-Native 智能Data平台的典型应用场景、行业解决方案及落地实践。

## 一、核心应用场景

### 1.1 智能数据分析

**场景描述**：业务人员通过自然语言查询数据，获得可视化图表和分析结论。

**典型用户问题**：
- "过去一个月销售收入是多少？"
- "哪个区域的销售额增长最快？"
- "销售额排名前十的客户有哪些？"
- "分析本季度销售趋势，找出异常波动原因"

**Cognida 能力支持**：
| 能力 | 说明 | 状态 |
|------|------|------|
| 自然语言问数 | 支持 NL2SQL，将自然语言转换为数据查询 | ✅ |
| GenUI 可视化 | AI 直接生成图表、仪表盘 | 🚧 |
| 数据结论生成 | 基于查询结果自动生成结论和建议 | ✅ |
| 意图澄清 | 问题模糊时主动澄清需求 | 🚧 |

| 能力 | 说明 | 状态 |
|------|------|------|

| 多源信息整合 | 联网搜索 + 知识库检索 | ✅ |
| 报告生成 | 结构化输出研究报告 | ✅ |

## 四、落地实施建议

### 4.1 业务梳理原则

**单一智能体原则**
- 一个智能体只支持一个单一场景
- 差异性大的业务场景需分开
- 避免在一个 Agent 中混杂多个数据查询场景

**数据集规划**
- 一个智能体关联的数据集不超过 5 个
- 总字段数不超过 300 个
- 避免跨表查询，尽量前置 ETL

**单意图原则**
- 一次问题交互只包含一个意图
- 避免复杂的多子句问题
- 引导用户分步提问

### 4.2 调优优先级

```
数据集质量 > 语义模型定义 > 知识库配置 > 提问描述优化
```

**1. 数据集质量（最重要）**
- 字段命名规范，消除歧义
- 维值标准化
- 数据及时性保障

**2. 语义模型定义**
- 配置同义词
- 配置业务术语
- 配置计算逻辑

**3. 知识库配置**
- 上传业务文档
- 配置计算规则
- 配置业务口径

**4. 提问描述优化**
- 使用明确的业务术语
- 指定时间范围
- 指定维度/指标

### 4.3 实施路径

**阶段一：试点验证（1-2 个月）**
- 选择 1-2 个业务场景
- 配置 1-2 个智能体
- 验证核心功能
- 收集用户反馈

**阶段二：规模推广（3-6 个月）**
- 扩展到 5-10 个业务场景
- 完善 Agent 能力
- 建立运营机制
- 培养用户习惯

**阶段三：全面深化（6-12 个月）**
- 覆盖主要业务场景
- 实现Agent协作
- 建立知识沉淀体系
- 持续优化迭代
